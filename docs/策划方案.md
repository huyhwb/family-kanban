# 家庭看板（Family Kanban）— 需求与策划方案

> 版本：v1.0 　|　 日期：2026-10-16 　|　 状态：待确认
> 项目目录：`C:\Users\cqdjh\WorkBuddy\面板`

---

## 一、项目定位

家庭内部共用的一块**常驻信息面板**。以 Docker 容器部署在家庭内网主机（NAS / 小主机 / 树莓派）上，平板浏览器横屏访问 `http://<主机IP>:12333` 即为满屏看板，用于统一承载：

| 承载内容 | 说明 |
| --- | --- |
| 时间与日期 | 实时时钟 + 公历 / 农历 / 节气 / 节日 / 调休 |
| 家庭日程 | 按月查看日期，点选日期即筛选出当天的待办 |
| 家庭待办 | 支持四象限（重要紧急矩阵）与清单两种视图 |
| 成员分工 | 每位家庭成员一个头像入口，点击即查看其专属待办 |
| 定时提醒 | 面向吃药、喝水、打卡等高频重复场景的多次提醒 |

**非目标（明确不做）**：不做公网访问、不做多租户、不做账号体系、不做移动端竖屏优化、不接入第三方日历（Google/Outlook）。

## 二、部署与运行形态

| 项 | 决策 |
| --- | --- |
| 部署方式 | Docker 单容器（多阶段构建，前端产物由后端静态托管） |
| 对外端口 | `12333`（容器内外一致，`-p 12333:12333`） |
| 持久化 | 卷映射 `./data:/data`，内含 `kanban.db` 与 `uploads/`（头像） |
| 时区 | 容器 `TZ=Asia/Shanghai`，服务端与前端时间口径一致 |
| 访问控制 | 局域网免密直连，无登录页 |
| 客户端 | 平板浏览器横屏；建议配「常亮 + 自动打开浏览器」或 kiosk 模式 |
| 重启策略 | `restart: unless-stopped` |

### 3.1 ① 日历区

- 月视图网格，默认周一为每周起始（下拉可切换为周日起始）。
- **每个日期格内容**（自上而下）：公历日（大字）→ 农历日 / 节气 / 节日（小字）。节日与节气优先于农历日显示。
- **角标**：`休`（红底）与 `班`（灰底）标注法定节假日与调休上班日。
- **今天**：蓝色圆角方框高亮，左上角带「今」角标。
- **选中日**：与外框区分的高亮态（实心主色描边）。
- **非本月日期**：置灰，弱化显示（可点击并自动跳月）。
- **顶部信息条**（对应截图的星期五 / 2026年10月 / 世界粮食日区域）：
  - 左：星期 + 日期大字 + 「今天」标记
  - 中：`YYYY年M月` + `第N天，第N周`
  - **右：实时时钟 `HH:MM:SS`（每秒刷新）+ 公历日期行** ← 对应需求「右上角空白处显示时间」
- **工具栏**：年份下拉、`◀ M月 ▶`、`放假安排`下拉、起始日下拉、右侧「返回今天」按钮。
- **底部农历详情**：`农历九月初七` / `丙午[马]年 戊戌月 癸亥日`（含干支纪年）。

**数据源**：
- 农历 / 节气 / 干支：`lunar-javascript`（MIT，纯前端可算，无需联网）。
- 法定节假日与调休：内置 JSON（覆盖 2024–2027），并提供设置页手动更新入口。

### 3.2 ② 待办区

**两种视图，右上角分段按钮切换：**

| 视图 | 说明 |
| --- | --- |
| 四象限视图 | 2×2 矩阵：重要且紧急 / 重要不紧急 / 不重要但紧急 / 不重要不紧急。未设置象限的待办归入「未分类」区 |
| 清单视图 | 单列列表，按清单分组，顶部下拉切换清单；支持按时间排序 |

**筛选状态条**：区域顶部显示当前筛选上下文，如 `10月16日 · 全部成员 · 未完成`，右侧带 × 清除按钮。

**单个待办项**：
- 左侧空心圆圈 → 点击展开操作弹层：**完成 / 编辑 / 删除**（三选一）。
- 完成态：圆圈填充 + 标题删除线 + 整行置灰。
- 行内信息：标题、时间（`HH:mm` 或 `HH:mm-HH:mm`）、归属成员头像小圆点。

**添加待办**：区域底部固定「＋ 添加待办」按钮，打开表单：
`标题` · `日期`（默认当前选中日）· `时间` · `归属成员` · `象限` · `清单` · `备注` · `提醒规则`（可折叠）· **常用语快捷选择**（按所选成员加载其常用语 chips，点击即填入标题）。

**联动规则**：
- 点击左侧日历某日 → 中间筛选该日待办。
- 点击右侧某成员 → 中间筛选该成员待办。
- 两者可叠加：`日期 + 成员` 同时生效。
- 「全部」= 不按成员筛选。

### 3.3 ③ 人物栏

- 顶部：**全部**（聚合视图）。
- 以下：家庭成员头像圆，自上而下。默认内置 6 个角色：爷爷、奶奶、爸爸、妈妈、姐姐、弟弟。
- 头像下方显示名称，可自定义。
- 选中态：主色描边 + 轻微放大。
- 是否显示由「设置 → 成员 → 是否在主页显示」控制；隐藏的成员不在栏中展示，但仍可在历史数据与统计中检索。
- 最底部：**⚙ 设置**按钮。

### 3.4 补充：提醒浮层

- 触发时全屏半透明遮罩 + 居中卡片，显示：待办标题、归属人、触发时间、`已完成` / `稍后提醒（+10分钟）` / `跳过` 三个按钮。
- 同时播放提示音（内置音频 + Web Audio 合成兜底）。
- 未处理提醒会在待办区顶部显示红色提醒条，避免被遮挡而彻底遗漏。

## 五、数据模型（SQLite）

```sql
-- 家庭成员
CREATE TABLE member (
  id             TEXT PRIMARY KEY,
  role_key       TEXT UNIQUE,      -- grandpa/grandma/dad/mom/sister/brother（内置角色）
  name           TEXT NOT NULL,    -- 显示名称，可自定义
  avatar_preset  TEXT,             -- 内置卡通头像标识
  avatar_file    TEXT,             -- 上传头像的相对路径（优先生效）
  sort_order     INTEGER DEFAULT 0,
  visible_on_home INTEGER DEFAULT 1,
  is_virtual     INTEGER DEFAULT 0, -- 1 = "全部"虚拟成员
  created_at     TEXT NOT NULL
);

-- 常用语
CREATE TABLE phrase (
  id         TEXT PRIMARY KEY,
  member_id  TEXT,                 -- NULL 表示全局常用语
  text       TEXT NOT NULL,
  sort_order INTEGER DEFAULT 0,
  FOREIGN KEY(member_id) REFERENCES member(id) ON DELETE CASCADE
);

-- 待办
CREATE TABLE todo (
  id         TEXT PRIMARY KEY,
  title      TEXT NOT NULL,
  note       TEXT,
  due_date   TEXT NOT NULL,        -- YYYY-MM-DD
  due_time   TEXT,                 -- HH:mm，可空
  end_time   TEXT,                 -- HH:mm，可空（时间段）
  quadrant   INTEGER,              -- 1 重要紧急 2 重要不紧急 3 紧急不重要 4 都不  NULL 未分类
  member_id  TEXT,
  list_name  TEXT DEFAULT '默认清单',
  status     TEXT DEFAULT 'pending', -- pending / done / skipped
  done_at    TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY(member_id) REFERENCES member(id) ON DELETE SET NULL
);
CREATE INDEX idx_todo_date   ON todo(due_date, status);
CREATE INDEX idx_todo_member ON todo(member_id, status);

-- 提醒规则（吃药/打卡场景）
CREATE TABLE reminder_rule (
  id             TEXT PRIMARY KEY,
  todo_id        TEXT NOT NULL,
  start_date     TEXT NOT NULL,    -- YYYY-MM-DD
  start_time     TEXT NOT NULL,    -- HH:mm
  times_per_day  INTEGER NOT NULL, -- 每天几次
  interval_hours REAL    NOT NULL, -- 隔几小时
  duration_days  INTEGER NOT NULL, -- 共提醒多少天
  enabled        INTEGER DEFAULT 1,
  created_at     TEXT NOT NULL,
  FOREIGN KEY(todo_id) REFERENCES todo(id) ON DELETE CASCADE
);

-- 提醒实例（一次具体触发，服务端生成，保证刷新不丢）
CREATE TABLE reminder_instance (
  id         TEXT PRIMARY KEY,
  rule_id    TEXT NOT NULL,
  todo_id    TEXT NOT NULL,
  fire_at    TEXT NOT NULL,        -- ISO 本地时间
  status     TEXT DEFAULT 'pending', -- pending / done / snoozed / skipped / expired
  handled_at TEXT,
  FOREIGN KEY(rule_id) REFERENCES reminder_rule(id) ON DELETE CASCADE
);
CREATE INDEX idx_ri_fire ON reminder_instance(status, fire_at);

-- 完成记录（统计与打卡历史）
CREATE TABLE completion_log (
  id        TEXT PRIMARY KEY,
  todo_id   TEXT NOT NULL,
  member_id TEXT,
  action    TEXT NOT NULL,         -- done / skipped
  act_date  TEXT NOT NULL,         -- YYYY-MM-DD
  acted_at  TEXT NOT NULL
);
CREATE INDEX idx_cl_date   ON completion_log(act_date);
CREATE INDEX idx_cl_member ON completion_log(member_id, act_date);

-- 全局设置 KV
CREATE TABLE app_setting (
  key   TEXT PRIMARY KEY,
  value TEXT
);
```

**提醒时刻生成算法**（服务端 `node-cron` 每日 00:05 预生成，启动时补齐）：
```
第 i 天（0 ≤ i < duration_days）的第 j 次（0 ≤ j < times_per_day）触发时刻 = 
    start_date + i 天 + start_time + j × interval_hours
```
示例：`start_time=08:00, times_per_day=3, interval_hours=6, duration_days=7`
→ 每天 `08:00 / 14:00 / 20:00`，连续 7 天，共 21 次。

## 七、技术架构

### 7.1 技术选型

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 前端框架 | Vue 3 + Vite + Pinia | 响应式心智轻、打包体积小、平板端首屏快 |
| 样式 | 原生 CSS + CSS 变量（自研组件） | 避免重型 UI 库拖累渲染，便于按平板尺寸精调 |
| 日历 | 自研月视图组件 + `lunar-javascript` | 农历/节气/干支本地计算，无需联网 |
| 后端 | Node 22 + Express | 与前端同语言，镜像体积小，`better-sqlite3` 同步 API 简洁 |
| 数据库 | SQLite (`better-sqlite3`) + WAL | 家庭量级（万级记录）性能充裕，零运维 |
| 调度 | `node-cron` | 生成提醒实例、过期清理 |
| 上传 | `multer` + `sharp` | 头像压缩到 256×256 webp |
| 部署 | Docker 多阶段构建 | 单镜像单容器，前端产物由 Express 托管 |

### 7.3 关键实现要点

1. **首屏性能**：`/api/bootstrap` 单请求聚合首屏全部数据，目标 `<500ms` 可交互。
2. **提醒可靠性**：提醒实例持久化在数据库，前端仅做展示与轮询。刷新页面 / 重启平板不会丢失未处理提醒；服务端对超过 30 分钟未处理的实例标记 `expired`。
3. **声音自动播放限制**：浏览器要求用户先有交互。设置页提供「测试提示音」按钮，首次点击即解锁音频上下文，之后自动播放生效。
4. **时钟**：前端 `requestAnimationFrame` + 1s 节流驱动，与服务器时间定期校准（`/api/health` 返回服务端时间戳）。
5. **头像存储**：上传文件存 `data/uploads/`，文件名用 UUID，数据库仅存相对路径，导出备份时可 `?includeFiles=1` 打包 base64。

## 八、平板适配规范

| 项 | 规范 |
| --- | --- |
| 目标分辨率 | 1280×800 / 1920×1200 / 2560×1600 横屏 |
| 三栏比例 | `34% / 46% / 20%`，各栏设 `min-width` 防止塌陷 |
| 触控目标 | 所有可点元素 ≥ 44×44px |
| 字号 | `clamp()` 自适应，主标题 20–28px，正文 14–18px，日期大字 40–64px |
| 禁止手势 | `user-select:none`、`touch-action:manipulation`、viewport `maximum-scale=1` |
| 抗烧屏 | 建议开启平板系统的屏幕保护 / 像素微移；面板本身避免长时间纯静态高对比块 |
| 断网容错 | 后端不可达时前端展示缓存快照与「连接中断」提示条，恢复后自动重连 |
